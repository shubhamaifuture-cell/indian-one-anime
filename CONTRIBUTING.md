# Contributing to DUBKAMI

Thank you for your interest in contributing to DUBKAMI - Indian One Anime!

## 🎯 Code of Conduct

We are committed to providing a welcoming and inclusive environment for all contributors.

### Our Standards
- Be respectful and inclusive
- Welcome all experience levels
- Focus on constructive feedback
- Respect different opinions
- Maintain professionalism

---

## 🚀 How to Contribute

### 1. Getting Started

- Fork the repository
- Clone your fork: `git clone https://github.com/YOUR_USERNAME/indian-one-anime.git`
- Create a new branch: `git checkout -b feature/your-feature-name`

### 2. Making Changes

- Follow the existing code style
- Write clear, descriptive commit messages
- Keep changes focused and atomic
- Update relevant documentation

### 3. Testing

- Test your changes thoroughly
- Ensure no breaking changes
- Test on multiple devices/browsers
- Document test cases

### 4. Submitting Changes

1. Push to your fork
2. Create a Pull Request with:
   - Clear title
   - Detailed description
   - Screenshots (if applicable)
   - Link to related issues

---

## 📋 Pull Request Guidelines

### PR Title Format
```
[TYPE] Brief description
```

**Types**: feature, bugfix, improvement, docs, chore

### PR Description Template
```markdown
## Description
Brief description of changes

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change
- [ ] Documentation update

## Testing
- [ ] Tested on Android
- [ ] Tested on iOS
- [ ] Tested on Web

## Related Issues
Closes #(issue number)
```

---

## 🐛 Bug Reports

### Before Reporting
- Check existing issues
- Search closed issues
- Test with latest version

### Bug Report Format
```markdown
## Bug Description
Clear description of the bug

## Steps to Reproduce
1. Step 1
2. Step 2
3. ...

## Expected Behavior
What should happen

## Actual Behavior
What actually happens

## Screenshots
[If applicable]

## Environment
- Device: [e.g., Samsung Galaxy S21]
- OS: [e.g., Android 12]
- App Version: [e.g., 1.0.0]
```

## 📦 Commit Guidelines

### Format
```
<type>: <subject>

<body>

<footer>
```

### Types
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation
- `style`: Code style
- `refactor`: Code refactoring
- `test`: Adding tests
- `chore`: Maintenance

### Example
```
feat: Add AI recommendation engine

Implement machine learning model for personalized anime recommendations
based on user viewing history and preferences.

Closes #123
```

## 🔄 Review Process

1. **Automated Checks**: Tests and lint checks run automatically
2. **Code Review**: Team reviews for code quality and standards
3. **Discussion**: Feedback and suggestions provided
4. **Revision**: Update PR based on feedback
5. **Approval**: Merged once approved
